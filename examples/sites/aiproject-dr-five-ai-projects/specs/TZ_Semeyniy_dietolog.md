# Техническое задание: Web-приложение «Семейный диетолог: Бюджет» (Вариант 1: React + Python)

## 1. Общие сведения
**Цель продукта:** Снизить когнитивную нагрузку при планировании питания, обеспечить соответствие рациона медицинским нормам (калораж) и финансовым ограничениям.
**Целевая аудитория:** Семьи из 2–3 человек пенсионного возраста (60+).
**Формула расчета:** Миффлин-Сан Жеор.
**Учет специфики:** Мягкая термообработка, ограничение красного мяса, акцент на кальций и клетчатку, минимум соли и сахара.

## 2. Функциональные требования

### 2.1. Личный кабинет пользователя (Фронтенд — React)
*   **Профиль семьи:** Создание 1–3 профилей (пол, вес, рост, возраст, активность).
*   **Расчет БЖУ:** 
    *   Мужчины: $10 \times \text{вес} + 6.25 \times \text{рост} - 5 \times \text{возраст} + 5$
    *   Женщины: $10 \times \text{вес} + 6.25 \times \text{рост} - 5 \times \text{возраст} - 161$
    *   Применение коэффициента активности (1.2 – 1.55).
*   **Настройки бюджета:** Выбор периода (неделя/месяц), ввод предельной суммы (только стоимость сырьевого набора).
*   **Генерация меню:** 
    *   Таблица на 7 дней (Завтрак, Обед, Ужин, Перекус).
    *   Вывод БЖУК порции и дня.
    *   Итоговый список покупок с общим весом.
*   **UI/UX требования:** Шрифт от 16px, высокий контраст, крупные кликабельные элементы, поддержка экранных дикторов.

### 2.2. Админ-панель (Бэкенд — Django / FastAPI)
*   **База продуктов:** Название, категория, цена (за кг/л), БЖУК на 100г, срок годности.
*   **База рецептов:** Название, фото, технологическая карта (граммовка), сложность, время, теги (бюджетное, без сахара, мягкая текстура).
*   **Логика алгоритма:** Оптимизация меню под калории пользователей и общий бюджет. Приоритет сезонным и бюджетным продуктам. Ограничение повторяемости блюд (не чаще 2 раз в неделю).

## 3. Нефункциональные требования
*   **Производительность:** Генерация меню — до 5 секунд.
*   **Отказоустойчивость:** Сохранение последнего меню в Local Storage.
*   **Инфраструктура:** Docker-контейнеры (Yandex Cloud или аналог).

## 4. Технический стек (Вариант 1)

| Слой | Технология | Обоснование |
|---|---|---|
| **Фронтенд** | React (Vite) + MUI / Ant Design | Готовая библиотека крупных компонентов для аудитории 60+, динамический пересчет БЖУ. |
| **Бэкенд** | Python (Django или FastAPI) | Лучший язык для математических алгоритмов. У Django есть готовая админка «из коробки». |
| **База данных** | PostgreSQL | Надежность, поддержка сложных JSONB-запросов для структуры рецептов, хорошая интеграция с Python. |
| **Инфраструктура** | Docker | Изоляция окружения, простота развертывания и масштабирования. |

## 5. Критерии готовности (MVP)
1.  Регистрация профиля семьи (2-3 человека) с сохранением данных.
2.  Корректный расчет суточной нормы калорий по формуле Миффлина-Сан Жеора.
3.  Ввод бюджета на неделю.
4.  Генерация меню на 7 дней, где сумма калорий каждого участника $\approx$ его норме.
5.  Автоматическое формирование списка покупок.
6.  Стоимость корзины $\le$ заданному бюджету.
7.  Работающая админ-панель для добавления 10 тестовых рецептов и 50 продуктов.
